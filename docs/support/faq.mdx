# Frequently Asked Questions

---

## Installation & Setup

<AccordionGroup>
  <Accordion title="Which Windows 11 builds are supported?" icon="windows" iconType="duotone">
    JarvisOS v30.05.26 supports the following Windows 11 builds:

    * `22000` (21H2)
    * `22621` (22H2)
    * `22631` (23H2)
    * `26100` (24H2)
    * `26200`
    * `27686`

    <Warning>Always start from a **clean, unmodified Windows install**. Do not apply JarvisOS on top of an existing tweaked system.</Warning>
  </Accordion>

  <Accordion title="Can I apply JarvisOS on top of an existing Windows install?" icon="triangle-exclamation" iconType="duotone">
    Technically yes — AME Wizard can run on an existing install. But it is strongly recommended to start from a fresh Windows installation for a predictable, clean result.

    Any third-party tweaks, debloat scripts, or registry modifications already present will conflict with AME's configuration and may cause instability.
  </Accordion>

  <Accordion title="The AME Wizard shows a popup modal, not a full-screen UI. What's wrong?" icon="window-maximize" iconType="duotone">
    This means you may have an older version of the playbook. Download the latest `JarvisOS_30.05.26.apbx` from [GitHub Releases](https://github.com/PsProsen-Dev/JarvisOS/releases/latest).

    The current build uses Privacy+ style DependsOn linking which forces the full-screen selection flow in AME Wizard.
  </Accordion>

  <Accordion title="The system froze or restarted unexpectedly during install. What do I do?" icon="power-off" iconType="duotone">
    If the system force-shut down during the mitigation phase, your Windows install may be in an inconsistent state. The safest path is a clean reinstall.

    Do not attempt to resume or repair the AME process mid-run.
  </Accordion>
</AccordionGroup>

## Core Applications

<AccordionGroup>
  <Accordion title="Where is the Microsoft Store?" icon="store" iconType="duotone">
    **Purged.** The Microsoft Store and its background Appx infrastructure are a significant telemetry vector, so they are surgically removed.

    To sideload any necessary UWP app, use **App Fetch**:
    <CodeGroup>
    ```powershell Sideload App
    app-fetch install <URL_or_local_path>
    ```
    </CodeGroup>

    For standard software, use the preserved **WinGet** package manager:
    <CodeGroup>
    ```powershell WinGet
    winget install <PackageName>
    ```
    </CodeGroup>
  </Accordion>

  <Accordion title="Where are Edge, OneDrive, Teams, and Xbox?" icon="ghost" iconType="duotone">
    **Eradicated.** All consumer Microsoft apps, including Cortana and Game Bar, are uninstalled during the playbook run. They will not be reinstalled by Windows Update in this configuration.

    Your selected browser (Brave, LibreWolf, or Zen) handles web browsing. Edge cannot be easily restored.
  </Accordion>

  <Accordion title="Can I use WSL2, Docker, and Hyper-V?" icon="server" iconType="duotone">
    **Absolutely.** All three are explicitly preserved and protected from the component removal passes.

    Verify WSL2 is active:
    <CodeGroup>
    ```powershell Verify WSL2
    wsl --list --verbose
    ```
    ```powershell Install Ubuntu
    wsl --install -d Ubuntu
    ```
    </CodeGroup>
  </Accordion>
</AccordionGroup>

## Security & Updates

<AccordionGroup>
  <Accordion title="How do I get security updates?" icon="shield-check" iconType="duotone">
    Automatic updates are suppressed. Patch on your schedule using the **AtlasOS Toolbox**:

    <Steps>
      <Step title="Enable Updates">
        Open AtlasOS Toolbox → Windows Update → **Enable**
      </Step>
      <Step title="Install Patches">
        Run Windows Update normally and install security patches.
      </Step>
      <Step title="Lock Down">
        Open AtlasOS Toolbox → Windows Update → **Disable**
      </Step>
    </Steps>

    <Note>Do not use the Windows Settings app to manage updates — it will not respect JarvisOS's lockdown configuration.</Note>
  </Accordion>

  <Accordion title="Is Windows Defender active?" icon="shield-virus" iconType="duotone">
    Yes, by default. JarvisOS leaves Defender enabled. Removing it requires trusting your entire software supply chain.

    If you want to disable it entirely, run:
    <CodeGroup>
    ```powershell Disable Defender
    ame-settings-cli set defender --state off
    ```
    </CodeGroup>
  </Accordion>
</AccordionGroup>
